# Micro Moments Index — Ambiguity Fallback

## Purpose

This file exists only for **genuine micro-domain ambiguity or future unregistered domains**.

For normal runtime work, `references/reference-router.md` contains the direct scene-context → micro file map. If the scene clearly matches that map, do not load this index.

Micro Moments are small physical behaviors that create lived-in texture.

They answer:

> While the event is happening, what tiny human behavior makes it feel observed rather than staged?

This index routes to a **small micro-detail set**. It is not permission to read every domain.

## Loading rules

- When a Primary Scene Domain has already been selected, follow that domain to its matching micro file when one exists; do not re-scan or reclassify.
- Load `universal.md` only when general body/object behavior is useful.
- Load one domain file when domain-specific texture is needed.
- Load both universal + one domain only when each serves a distinct need.
- Do not use Micro Moments as a checklist.
- Prefer 1–3 meaningful micro behaviors in a scene over dense decoration.
- Do not add detail that fights the main action or overloads AI generation.

## Distinction from Mother Motif

Mother Motif:
- why an event exists,
- what situation creates action/reaction.

Micro Moment:
- how a person physically inhabits that event.

Example:

Motif: Recover  
Scene Event: sit on a bench after a ride  
Micro Moments:
- place shopping bag between shoes,
- push loose hair behind ear,
- twist bottle cap before handing it over,
- stand up with a slight delay.

## Selection test

A Micro Moment is useful when it:
- reveals state,
- reveals habit/personality,
- connects props,
- creates a believable transition,
- adds physical consequence,
- supports relationship behavior.

Remove it when it exists only to make the description longer.
