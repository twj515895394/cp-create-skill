# Scene Specificity and Content Map

## 1. The viewer must understand what the video actually contains

Before writing the director shot table, produce a **Content Map / Scene Route** for any complete Vlog.

The map must make the entire runtime understandable at a glance.

For a 60-second video, the reader should be able to answer:
- Where are the couple at each stage?
- What specifically happens there?
- Which moments are attractions, and which are ordinary visit/life moments?
- In what order?
- What relationship behavior is visible?
- How does day/time/emotion change?
- What is the final payoff?

If the user cannot understand the video from this map, the plan is too vague.

## 2. Concrete scene event, not mandatory project

Every section needs a **concrete scene event**, but not every section needs a "project."

Valid scene-event types include:
- ride / attraction / game,
- entrance / navigation,
- walking / wandering,
- queue / waiting,
- food / drink,
- shopping,
- photography,
- parade/show viewing,
- rest,
- transport,
- practical care,
- spontaneous small event,
- night-time spectacle.

Examples:
- "七个小矮人矿山车上车站台：入座、压安全杆、等待发车"
- "米奇大街边走边逛：女生连续被橱窗吸引停下，男生走出两步后回头"
- "爆米花摊：接过桶后边走边吃，女生趁男生看路时抓一大把"
- "商店镜子前：女生把夸张发箍扣到男生头上，男生先面无表情看镜子再摘下来"
- "喷泉/休息座椅：两人把购物袋放脚边，男生拧水，女生低头揉脚"
- "巡游等待区：人群逐渐密起来，两人调整位置找视线"
- "烟花观赏区：提前站定，周围人群安静下来，两人共同抬头"

Concrete does not mean attraction-heavy. It means observable and spatially specific.

## 3. Venue-driven scene selection

Do not merely make existing user ideas more specific. When a destination implies meaningful experiences, actively design a believable mix.

Evaluate candidate scenes by:
- destination identity,
- visual distinctiveness,
- action/reaction potential,
- relationship opportunity,
- pacing value,
- physical realism,
- runtime value.

Select a mix of strong events and ordinary moments.

Cross-reference only: `creative-expansion.md`. Load it only when selected by `reference-router.md` for the current task/stage.

## 4. Required content-map fields

Use a compact table with:

| Field | Requirement |
|---|---|
| Runtime range | Approximate section duration |
| Concrete place | Specific spatial setting |
| Scene-event type | Ride / walk / food / rest / shop / wait / show etc. |
| Concrete event | What physically happens |
| Relationship behavior | What visibly happens between them, if any |
| Visual anchor | Distinctive physical thing visible |
| Transition | Why/how the story moves onward |

Not every row needs a "dramatic function" or explicit "relationship progression." Some rows exist to create rhythm, realism, time flow, or spatial continuity.

## 5. Ban vague scene language

Avoid:
- 游玩项目
- 逛一逛
- 互动一下
- 吃点东西
- 看风景
- 休息一下
- 玩设施
- 随便走走

Prefer:
- 走进主题街区后女生被右侧橱窗吸引停下，男生多走两步才发现她没跟上
- 在焦糖爆米花摊点单，拿到纸桶后边走边分着吃
- 坐到喷泉旁长椅，把购物袋放脚边，女生揉脚，男生从包里找水
- 在巡游路线旁跟着人群换到第二排，女生踮脚找视线
- 进入过山车站台，跨进车厢并压下安全杆

## 6. Real-world activity realism

When designing a recognizable activity, include enough physical stages and constraints to feel real.

### Roller coaster
Possible beats:
- queue,
- platform,
- entering car,
- restraint,
- dispatch,
- lift/anticipation,
- drop/wind,
- limited body movement,
- post-ride recovery.

### Food stall
Possible beats:
- read menu,
- point/order,
- receive item,
- open packaging,
- first taste,
- share/steal,
- carry while walking.

### Rest
Possible beats:
- put bags down,
- sit,
- adjust shoes,
- rub legs/feet,
- drink,
- check phone/map,
- watch passers-by,
- stand back up reluctantly.

### Shop
Possible beats:
- browse shelf,
- try accessory,
- compare choices,
- look in mirror,
- take candid photo,
- carry purchase out.

Use only the stages needed by the runtime.

## 7. Real venue rule

If the user names a real venue:
- proactively research actual venue experiences when tools are available and useful,
- include more than headline attractions when appropriate,
- do not invent branded names,
- use real or safely generic spatial/event types,
- ask the user only when personal preferences/constraints materially affect the choice.

Specificity must not become fabrication.

## 8. Spatial progression

Avoid teleporting.

A believable theme-park route might be:
entrance → themed street → attraction zone → snack stop → shop/wander → rest area → parade route → evening viewing zone.

This is an example, not a required route.

Transitions may use:
- walking,
- signage/map,
- queue exits,
- carrying newly acquired food/merchandise,
- changing light,
- sound bridge,
- crowd flow.

## 9. Visual anchors

Every major scene should have concrete anchors.

Examples:
- entry turnstile,
- folded map,
- themed storefront,
- queue railing,
- coaster restraint,
- popcorn bucket,
- shopping bag,
- mirror/headband,
- bench/fountain,
- parade float,
- illuminated castle,
- fireworks sky.

## 10. Content density and breathing room

Do not confuse "rich content" with "many projects."

For short videos:
- choose fewer strong moments,
- allow ordinary scenes between peaks,
- use low-intensity moments to make high-intensity moments feel stronger,
- keep enough continuity that the viewer feels they spent time there.

## 11. Venue fingerprint test

Ask:
> If the venue name were replaced with “普通商场” or “普通公园”, would most of this plan still work unchanged?

If yes, strengthen venue identity.

But do **not** solve this only by adding more rides.

Venue fingerprint can come from:
- spatial design,
- themed streets,
- merchandise,
- food,
- signage/maps,
- crowd rituals,
- shows,
- queue behavior,
- night spectacles,
- recognizable props.

A destination is not merely a label, and it is not merely a list of attractions.
