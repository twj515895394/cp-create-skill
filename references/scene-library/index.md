# Scene Library Index — Ambiguity Fallback

## Purpose

This file exists only for **genuine routing ambiguity or future unregistered domains**.

For normal runtime work, `references/reference-router.md` contains the direct setting → file map. If the user's setting clearly matches that map, do not load this file.

This file is an index, not a creative scene catalog and not a discovery surface.

## Loading contract

0. First confirm that direct routing in `reference-router.md` cannot resolve the domain.
1. Identify the concrete environment or activity family.
2. Select **one domain file by default**.
3. Load a second domain only when the current story section genuinely crosses domains.
4. Do not read sibling domains for generic inspiration.
5. A domain file may mention Motif or Micro Moment categories, but that mention does not authorize loading those libraries unless the main Reference Router selects them.

## Ambiguity rule

### Primary Domain rule

Route by **what causally drives the characters' behavior/state**, not only by background.

Do not open multiple domain files to compare them. Use `references/reference-router.md` as the authoritative tie-break table.

Route by **what the characters are actually doing**, not only by background.

Examples:
- cooking dinner at home → Home Life; Shared Tasks only if the task/coordination itself is the creative focus.
- hotel room routine → Travel, not Home Life.
- outdoor music festival → Entertainment unless weather/outdoor survival behavior is the main engine.
- Christmas shopping mall date → City Daily; Holidays only when the holiday ritual meaning drives the scene.

## Scene Card schema

A mature scene entry should use only fields that materially help generation:

- Scene / subspace
- What people realistically do here
- Venue fingerprint / spatial identity
- Visual anchors
- Useful Motif families
- Relationship affordances
- State-in / state-out possibilities
- Transition possibilities
- AI-friendly framing notes
- Risk notes / physical constraints

Do not turn every field into a mandatory quota.

## Expansion rule

When adding new scene knowledge:
- prefer reusable human behavior over one-off plot scripts,
- preserve physical realism,
- avoid creator-specific signature gags or shot-for-shot copying,
- keep Micro Moments in the Micro Moment library rather than duplicating long lists here.
